## ข้อมูลปลายทางที่ตรวจจาก SQLite

หลังจบ flow และ restart:

- USER 3 แถว, ROOM 1 แถว ความจุ 2 สถานะ `full`
- ROOM_REQUEST 3 แถว: เอ `approved`, บี `rejected`, บีส่งใหม่ `approved`
- ROOM_MEMBER: เอ `left`, บี `approved`; ไม่มีแถวสมาชิกซ้ำสำหรับเจ้าของ
- MATCHES 2 แถวเป็นประวัติ โดย API คืนเฉพาะแมตช์เจ้าของ↔บีที่ยังเป็นสมาชิก
- `/members` ของเจ้าของและบีคืน `[เจ้าของ, บี]`; ของเอตอบ 403
- `PRAGMA foreign_key_check` ไม่มีข้อผิดพลาด
- เปรียบเทียบทุกฟิลด์ของ USER, ROOM, ROOM_REQUEST, ROOM_MEMBER, MATCHES ก่อน/หลัง restart แล้วตรงกัน

## วิธีให้ทีมทดสอบซ้ำอย่างปลอดภัย

รันจากราก repository ด้วย Node.js 26 และ dependencies ตาม lockfile:

```bash
npm ci
npm run build
export RM16_QA_DIR="$(mktemp -d "${TMPDIR:-/tmp}/roommatch-rm16.XXXXXX")"
```

ใช้คำสั่งนี้เปิดเว็บ QA ว่าง สามารถกด Ctrl+C แล้วรันคำสั่งเดิมซ้ำเพื่อทดสอบ restart
ได้ ตราบที่ยังใช้ `RM16_QA_DIR` เดิม หากพอร์ต 4349 ถูกใช้งานให้เปลี่ยนพอร์ตในโค้ด:

```bash
node --input-type=module - <<'JS'
import { randomBytes } from 'node:crypto';
import { existsSync, readFileSync, writeFileSync } from 'node:fs';
import { join } from 'node:path';
import { startRoomMatchServer } from './server/app.js';

const directory = process.env.RM16_QA_DIR;
if (!directory) throw new Error('Set RM16_QA_DIR to the temporary QA directory first');
const keyFile = join(directory, 'signing-key');
if (!existsSync(keyFile)) writeFileSync(keyFile, randomBytes(32).toString('hex'), { mode: 0o600 });
process.env.ROOMMATCH_TOKEN_SECRET = readFileSync(keyFile, 'utf8');
await startRoomMatchServer({
  host: '127.0.0.1', port: 4349,
  database: { filename: join(directory, 'qa.sqlite'), seed: false },
  uploadDirectory: join(directory, 'uploads'),
});
console.log('RM-16 QA: http://127.0.0.1:4349');
JS
```

1. เปิดเว็บดังกล่าว สมัครบัญชีทดสอบ 3 บัญชีด้วยข้อมูลจำลอง เลือกรหัสผ่านเฉพาะ QA ของตัวเอง
2. เจ้าของสร้างห้องความจุ 2 คน แล้วให้เอและบีส่งคำขอแยกกัน
3. ตรวจ empty/pending, ยกเลิกหน้าต่างยืนยัน, อนุมัติเอ, กันอนุมัติเกินความจุ และปฏิเสธบี
4. สลับบัญชีตรวจสมาชิกและช่องทางติดต่อ แล้วให้เอออก บีส่งใหม่ และเจ้าของอนุมัติบี
5. Refresh เส้นทาง `/requests?view=sent`, `/matches`, `/rooms/:id` แล้วหยุด/เปิด API ใหม่ตามข้างต้น ตรวจทั้ง 3 บัญชีซ้ำ
6. ตรวจหน้าต่างแคบ 320/390px, tablet 820px และ desktop 1440px รวม keyboard focus และปุ่มยืนยัน

ห้ามจำลอง trigger ล้มเหลวในฐานข้อมูลใช้งานจริง ใช้ integration tests เดิมซึ่งสร้างฐานแยก
สำหรับตรวจสิทธิ์ input ผิด การอนุมัติพร้อมกัน และ rollback ได้ด้วย:

```bash
node --test tests/requests.test.mjs tests/matches.test.mjs tests/ux-lifecycle.test.mjs
npm test
npm run build
```

การตรวจรอบนี้: `npm test` ผ่าน 116 ข้อ, build ผ่าน ไม่มี lint script ใน repository
ไม่ได้เพิ่ม tests ซ้ำหรือแก้ schema/API/UI ที่ทำงานอยู่แล้ว งานสิทธิ์คำชวนเพื่อนแยกตรวจใน RM-17
ผลนี้เป็น local acceptance ไม่ใช่ load test หลาย process หรือการรับรองอุปกรณ์จริงทุก browser
