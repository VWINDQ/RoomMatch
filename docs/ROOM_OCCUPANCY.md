# จำนวนผู้พักและที่ว่าง

`capacity` คือจำนวนคนสูงสุดที่ห้องรองรับ ไม่ใช่จำนวนคนที่รับเพิ่ม
ผู้ลงประกาศที่ปล่อยเช่าอย่างเดียวไม่ถูกนับเป็นผู้พัก หากพักเองต้องเลือก
**ฉันพักอยู่ในห้องนี้ด้วย** ในฟอร์มสร้างหรือแก้ประกาศ

| ห้องรองรับ | ผู้ลงประกาศพักด้วย | ผู้พักที่อนุมัติแล้ว | ที่ว่าง |
| --- | --- | --- | --- |
| 1 | ไม่พัก | 0 | 1 |
| 2 | ไม่พัก | 0 | 2 |
| 2 | พัก | 0 | 1 |
| 2 | ไม่พัก | 2 | 0 |

## API และฐานข้อมูล

- POST/PATCH ห้องใช้ `ownerIsResident` เป็น boolean เท่านั้น
- POST ที่ไม่ส่งค่านี้ถือว่า false; PATCH ที่ไม่ส่งจะคงค่าเดิม
- เพิ่ม `ROOM.owner_is_resident` ด้วย migration 005 ไม่มีการลบหรือสร้างข้อมูลใหม่แทนของเดิม
- ห้องเดิมกำหนด true เพื่อรักษาจำนวนที่ว่างและสถานะเดิม ส่วนห้องใหม่มีค่าเริ่มต้น false
- `memberCount` ยังคงนับเฉพาะสมาชิก approved ใน ROOM_MEMBER เพื่อรักษาสัญญา API เดิม
- `occupantCount = memberCount + (ownerIsResident ? 1 : 0)`
- `availableSlots = max(0, capacity - occupantCount)`
- เจ้าของไม่ถูกเพิ่มซ้ำใน ROOM_MEMBER และยังส่งคำขอเข้าห้องตัวเองไม่ได้
  หากต้องการพักเองให้แก้ตัวเลือกในประกาศ

การเปลี่ยนจำนวนผู้พัก/ตัวเลือกผู้ลงประกาศต้องไม่ทำให้เกินความจุที่ระบุ
API ตอบ 409 หากขัดกับจำนวนผู้พัก และแสดงข้อผิดพลาดใต้จำนวนผู้พัก
สามารถลดความจุพร้อมยกเลิกการพักของผู้ลงประกาศได้ในรายการเดียว หากยังรองรับผู้พักเดิมครบ

## ตัวกรอง คำขอ และสมาชิก

- `minSlots` กรองจำนวนที่ว่างสำหรับผู้พักใหม่ ทั้งหน้ารวม ห้องโปรด และประกาศของฉัน
- `withFriend` ตรวจที่ว่างสำหรับคนที่ยังไม่ได้พักในห้อง ผู้ลงประกาศที่ไม่พักยังต้องใช้ที่ว่าง
- คำขอ pending ไม่จองที่ การอนุมัตินับเฉพาะผู้พักจริงและล็อกห้องก่อนตรวจจำนวน
- ห้องเต็มถูกซ่อนจากหน้ารวมตามกติกาเดิม การออกจากห้องคืนที่ว่างและเปิดรับใหม่
- เจ้าของลบประกาศได้เมื่อไม่มีผู้พัก การลบและอนุมัติคำขอใช้ล็อกห้องเดียวกันก่อนตรวจสถานะล่าสุด
- ห้องที่ยังมีผู้พักเลือก **พักประกาศ** เพื่อหยุดรับคำขอได้
- ห้องที่พักประกาศยังคง inactive แม้มีผู้พักออกหรือเปลี่ยนตัวเลือกผู้ลงประกาศ
- `/rooms/:id/members` แสดงผู้ลงประกาศเฉพาะเมื่อพักด้วย พร้อมสมาชิก approved
  ผู้ลงประกาศยังมีสิทธิ์จัดการคำขอและดูผู้พัก แม้ไม่ได้พักในห้องเอง
- MATCHES ยังคงเป็นบันทึกการอนุมัติระหว่างผู้ลงประกาศกับผู้เข้าพัก ไม่ได้ยืนยันว่าผู้ลงประกาศพักอยู่ด้วย
  จึงยังแสดงช่องทางติดต่อผู้ลงประกาศ โดยระบุบทบาทให้ชัดและไม่นับรวมในรายชื่อผู้พัก

## การตรวจสอบ

ใช้ PostgreSQL test schemas แยกจากข้อมูลจริงสำหรับ migration, ห้องเช่าคนเดียว,
เจ้าของพักด้วย, ตัวกรอง/หาห้องกับเพื่อน, การแก้จำนวนผู้พักและการพักประกาศ,
การอนุมัติพร้อมกันและการเปลี่ยนสถานะผู้ลงประกาศพร้อมอนุมัติ รวมถึง DB triggers
Component tests ตรวจค่าตั้งต้น การคำนวณที่ว่าง payload, validation และ unsaved guard
ของตัวเลือกผู้ลงประกาศโดยเฉพาะ

## โปรไฟล์ผู้พักที่ผู้สนใจดูได้

- การแชร์โปรไฟล์ปิดไว้เป็นค่าเริ่มต้นสำหรับทุกบัญชี รวมถึงบัญชีเดิมหลัง migration 009 ผู้ใช้เปิดหรือปิดได้ในหน้าแก้ไขโปรไฟล์
- API รายละเอียดห้องส่ง `sharedResidentProfiles` ให้ผู้สนใจที่เข้าสู่ระบบ โดยมีเฉพาะผู้พักปัจจุบันที่เปิดแชร์ พร้อมชื่อ รูป คำแนะนำตัว ไลฟ์สไตล์ และบทบาท
- ผู้พักที่ไม่แชร์ยังนับในจำนวนผู้พักจริง หน้าเว็บแสดงจำนวนคนที่ไม่ได้เปิดเผยโปรไฟล์โดยไม่ส่งรายการระบุตัวตนของคนเหล่านั้น
- สิทธิ์เดิมของผู้ลงประกาศและสมาชิกสำหรับรายชื่อผู้พักและช่องทางติดต่อยังใช้ตามเดิม
