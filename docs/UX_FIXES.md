## Database / API ที่ทีมต้องทราบ

- migration `005_ux_listing_and_request_lifecycle.sql` เพิ่ม nullable `ROOM.price_basis`, `ROOM.locality`, `ROOM.cost_notes` และสถานะ `ROOM_REQUEST.cancelled` โดยเก็บข้อมูลเดิม
- **ไม่เดาหน่วยราคา/ทำเลให้ประกาศเดิม**: NULL แสดงว่ายังไม่ระบุ เจ้าของต้องเติมเมื่อแก้ประกาศผ่านเว็บ ค่าใช้จ่ายเพิ่มเติมเว้นว่างได้
- API create/edit ยังรับ payload เดิมที่ไม่ส่งฟิลด์ใหม่ได้ เพื่อรักษา contract ของ frontend อื่น
- `POST /api/requests/:id/cancel`: เฉพาะผู้ส่ง pending; คืน `{ request }`; cancelled ซ้ำสำเร็จโดยไม่เปลี่ยนเวลาถอน, final อื่นตอบ 409
- `DELETE /api/rooms/:id/members/me`: เฉพาะสมาชิกปัจจุบัน/เดิม; ตั้ง `ROOM_MEMBER.status='left'`; เจ้าของต้องจัดการประกาศ; retry ปลอดภัย
- ห้อง full กลับ available เมื่อมีที่ว่าง แต่ห้อง inactive ยังคงพักประกาศ
- การอนุมัติหลังออก ใช้ member/match แถวเดิมและเวลาเข้าร่วมใหม่ ไม่สร้างคู่ซ้ำ ประวัติ ROOM_REQUEST แต่ละครั้งยังอยู่
- request DTO เพิ่ม `membershipActive` เพื่อแยกประวัติอนุมัติจากการเป็นสมาชิกปัจจุบัน; room detail เพิ่ม `isMember`; match เพิ่ม `otherRole`
- `GET /api/rooms` รองรับ `minSlots=1..100`, `priceBasis=per_room|per_person`, `withFriend=<accepted friend id>`; ไม่ใช่การจองกลุ่ม แต่ละคนยังขอแยกกัน
- เพิ่ม `_roommatch_migrations` เป็น ledger ภายใน ไม่ใช่ entity ธุรกิจใน ER: จดชื่อไฟล์ที่รันแล้ว ทำให้ migration Favorites 004 ที่มา merge หลัง UX 005 ไม่ถูกข้ามเพราะ user_version สูงกว่า
- ให้ใช้ migration runner ของแอป อย่านำ SQL ALTER TABLE มารันซ้ำด้วยมือ ไม่มีการย้าย database หรือเปลี่ยนที่เก็บรูป

ก่อนใช้กับข้อมูลจริงให้หยุดเซิร์ฟเวอร์และสำรอง SQLite ตามวิธีของทีม รันแอปตามปกติจะ migrate ให้อัตโนมัติ ไม่ต้องลบ DB หรือ seed ใหม่

## ขอบเขตที่ยังต้องทำในงาน production แยกต่างหาก

นี่คือการแก้ feedback รอบ UX ไม่ใช่การรับรอง production: ยังไม่มี group booking, moderation/block/unfriend, request expiration, การนำสมาชิกออกโดยเจ้าของ หรือการคำนวณระยะทางจริง ช่องทางติดต่อที่เคยดู/คัดลอกไปแล้วเรียกคืนไม่ได้ และการออกจากห้องในระบบไม่ได้ยกเลิกข้อตกลงค่าเช่าภายนอก

งานนี้แตะส่วนกลางและหน้าของคนที่ 1/2 ตามการอนุญาตให้แก้ทั้งหมด จึงยังมีโอกาส conflict เมื่อรวม Favorites/Profile/บัญชี ให้รักษา markup/validation ของเพื่อนพร้อมฟิลด์และพฤติกรรมใหม่ ไม่แทนไฟล์ทั้งก้อน; ไม่ทำซ้ำงาน age/date format/phone validation ที่เพื่อนกำลังทำ
